# P-Downloader Baseline Audit & Fault Baseline (2026-10-30)

## Overview
Baseline evaluation of existing download engine (`core/segment.py`) against local deterministic HTTP fault injection fixture (`tests.support.http_origin.FaultOrigin`).

## Test Results: Baseline Fault Failures
Running `python -m unittest tests.test_http_faults`:
- `test_fixture_empty_body`: **PASS** (fixture returns valid 200/416 responses)
- `test_fixture_normal_range`: **PASS** (fixture verifies 206 Partial Content slicing)
- `test_fixture_range_ignored`: **PASS** (fixture simulates server returning 200 to Range GET)
- `test_fixture_wrong_content_range`: **PASS** (fixture returns contradictory Content-Range)
- `test_empty_body_finishes`: **FAIL** (`status` remained `downloading` instead of cleanly completing 0-byte transfer)
- `test_interrupted_transfer_can_resume`: **FAIL** (`status` remained `downloading`, interrupted connection was not cleanly resumed to exact SHA-256)
- `test_unknown_length_finishes_at_eof`: **FAIL** (`status` remained `downloading` instead of completing on stream EOF)

## Identified Flaws in Legacy Engine
1. **P0 Range Ignored**: `core/segment.py` accepts HTTP 200 on ranged requests and seeks into file, corrupting data.
2. **P0 Zero-byte/Unknown-length completion gap**: Single-stream transfers with no `Content-Length` do not cleanly transition from downloading to completed upon EOF.
3. **P0 Unsafe In-place Preallocation**: Files are created directly at final destination before completion rather than using verified `.part` staging.
